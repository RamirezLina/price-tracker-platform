# Lógica de dominio MVP

## Entidades principales

### User
Representa un usuario de la plataforma.

Campos:
- id
- name
- email
- role
- createdAt

Roles:
- ADMIN
- USER

---

### Product
Representa un producto global independiente de la tienda.

Campos:
- id
- name
- brand
- category
- volumeLabel
- volumeMl
- normalizedVolumeMl
- description
- status
- createdAt

Ejemplo:
- Cicaplast Baume B5
- Marca: La Roche-Posay
- Volumen: 40 mL

---

### Store
Representa una tienda global.

Campos:
- id
- name
- mainUrl
- status
- createdAt

Estados:
- PENDING
- APPROVED
- REJECTED

---

### StoreProduct
Representa un producto específico dentro de una tienda.

Es la entidad principal sobre la que se ejecuta el scraping.

Campos:
- id
- productId
- storeId
- productUrl
- currentPrice
- discountPercentage
- finalPrice
- lastScrapedAt
- status
- createdAt

Ejemplo:
- Cicaplast Baume B5 40 mL en Farmatodo
- URL específica del producto

---

### UserStoreProduct
Representa que un usuario sigue o guarda un StoreProduct.

Campos:
- id
- userId
- storeProductId
- active
- createdAt

Regla:
Eliminar una asociación solo elimina UserStoreProduct.
No elimina Product, Store, StoreProduct ni PriceHistory.

---

### PriceHistory
Histórico global de precios de un StoreProduct.

Campos:
- id
- storeProductId
- price
- discountPercentage
- finalPrice
- scrapedAt
- success
- errorMessage

---

### StoreRequest
Solicitud de creación de tienda.

Campos:
- id
- requestedByUserId
- storeName
- mainUrl
- status
- adminComment
- createdAt
- reviewedAt

---

### ProductRequest (opcional)
Solicitud o registro de producto.

Campos:
- id
- requestedByUserId
- productName
- productUrl
- storeId
- status
- createdAt

Para el MVP:
- status = APPROVED automático

---

# Relación principal

Product + Store + URL = StoreProduct

User + StoreProduct = seguimiento del usuario

StoreProduct + Scraping = PriceHistory

---

# Regla principal del dominio

La unidad principal del sistema no es el producto aislado sino la combinación Producto + Tienda, llamada StoreProduct.

Cada StoreProduct contiene:
- URL específica
- precio actual
- descuento
- histórico de precios

Los usuarios únicamente asocian StoreProducts a su cuenta.

El histórico es global y compartido entre todos los usuarios que tengan asociado ese StoreProduct.

---

# Flujos principales

## Flujo 1: Asociar producto existente

1. Usuario busca producto.
2. Selecciona producto.
3. Selecciona tienda.
4. El sistema busca StoreProduct.
5. Si existe, crea UserStoreProduct.
6. El producto queda asociado a la cuenta.

---

## Flujo 2: Tienda no existe

1. Usuario encuentra producto.
2. Tienda no existe.
3. Usuario solicita nueva tienda.
4. Ingresa:
   - nombre
   - URL principal
5. Solicitud queda pendiente de aprobación.

---

## Flujo 3: Producto no existe

1. Usuario registra producto.
2. Ingresa:
   - nombre
   - URL del producto
   - tienda
3. Sistema crea Product.
4. Sistema crea StoreProduct.
5. Sistema crea UserStoreProduct.
6. Producto queda asociado al usuario.

Para MVP:
- creación inmediata.

---

## Flujo 4: Consultar valor

1. Usuario entra a Mis Productos.
2. Selecciona uno o varios productos.
3. Clic en Consultar valor.

4. Para cada producto seleccionado:
   - el sistema busca todos los StoreProduct asociados a ese producto dentro de la cuenta del usuario.

5. El sistema ejecuta scraping sobre cada StoreProduct.productUrl.

6. Por cada StoreProduct:
   - guarda PriceHistory
   - actualiza:
     - currentPrice
     - discountPercentage
     - finalPrice
     - lastScrapedAt

7. El usuario visualiza los precios actualizados.

Ejemplo:

Producto:
- Cicaplast Baume B5 40 mL

StoreProducts asociados:
- Farmatodo
- Cruz Verde
- Locatel

Al consultar valor:
- se scrapean las 3 URLs
- se actualizan los 3 precios
- se guarda histórico para cada tienda

# Permisos

## USER

Puede:
- iniciar sesión
- asociar productos
- registrar productos
- solicitar tiendas
- eliminar asociaciones
- ejecutar scraping manual
- consultar dashboard

## ADMIN

Puede:
- todo lo del USER
- aprobar tiendas
- rechazar tiendas
- gestionar solicitudes
- editar información
- ejecutar scraping manual

# Decisiones MVP

- Categoría inicial: Dermatología
- Login con Google
- Tienda nueva requiere aprobación
- Producto nuevo se crea inmediatamente
- StoreProduct nuevo se crea inmediatamente si existe la tienda
- Scraping manual únicamente
- Dashboard solo muestra productos asociados al usuario
- Histórico compartido globalmente por StoreProduct
